# Workflow: 1-on-1 Meeting Cycle

The full lifecycle of a 1-on-1 meeting: prepare → meet → analyse → extract memory.

---

## Routing

| User says… | Phase | Agent |
|------------|-------|-------|
| "Prep for my 1-on-1 with [name]" / "Help me prepare" / "What should I talk about?" | Prep | `agents/prep-agent.md` |
| "Here's my transcript" / "Analyse my meeting" / "How did it go?" | Analysis | `agents/analysis-agent.md` |
| "Extract memory" / "Save to memory" / "Memory" | Memory | `agents/memory-agent.md` |
| "Draft a follow-up to [name]" | Follow-up | `agents/writing-agent.md` |

If ambiguous, ask: *"Are you preparing for an upcoming meeting, or analysing one that's already happened?"*

---

## Context Loading

Before any phase, load:

1. `people/[name]/profile.md`
2. Up to 3 most recent files in `people/[name]/transcripts/`
3. Up to 3 most recent files in `people/[name]/talking-points/`
4. All files in `people/[name]/context/`

---

## Typical Flow

```
1. User: "Prep me for David"
   → Prep Agent runs → produces talking-points doc

2. [Meeting happens]

3. User: "Here's the transcript from David"
   → Analysis Agent runs → produces analysis

4. User: "Extract memory"
   → Memory Agent runs → produces tagged memory entries ([people], [self], etc.)

5. (Optional) User: "Draft a follow-up email to David"
   → Writing Agent runs → produces draft
```

Each phase can run independently. Memory works best after analysis, but can run from raw transcript if needed.

---

## File Outputs

| Phase | Output | Location |
|-------|--------|----------|
| Prep | Talking points doc | `people/[name]/talking-points/YYYY-MM-DD_prep.md` |
| Analysis | Analysis doc | `people/[name]/transcripts/YYYY-MM-DD_analysis.md` |
| Memory | Memory entries | `people/[name]/memory/YYYY-MM-DD_memory.md` |
| Follow-up | Draft message | Not saved (shared in chat for user to send) |
